# 阶段 8：测试、打包与发布

## 阶段目标

让项目从“能跑”进入“可以交付”的状态。

## 前置条件

- 阶段 7 已完成。
- 核心功能已经可用。

## 学习重点

- 单元测试
- 基础端到端测试
- 构建和打包
- 版本号
- GitHub Release
- 发布说明

## 开发任务

### 1. 添加 TypeScript 单元测试

优先测试纯函数：

- 标签标准化
- 搜索词解析
- 日期格式化
- 简单数据转换

推荐工具：

```text
Vitest
```

### 2. 添加基础界面测试

推荐工具：

```text
Playwright
```

最低测试流程：

1. 打开应用。
2. 新建笔记。
3. 输入标题和正文。
4. 搜索笔记。
5. 打开预览。

如果 Tauri 窗口自动化成本过高，可以先测试前端 Web 部分。

### 3. 添加 Rust 测试

如果阶段 6 写了 Rust 业务函数，则补 `cargo test`。

优先测试：

- 标签标准化
- command 内部纯函数
- 错误返回逻辑

### 4. 整理应用元信息

检查：

- 应用名称
- 版本号
- 图标
- 作者
- 描述
- Windows 打包配置

### 5. 执行生产构建

```bash
npm run tauri build
```

### 6. 本地安装测试

在构建完成后测试：

- 应用能启动。
- 数据库能创建。
- 主窗口可用。
- 搜索栏可用。
- 托盘可用。
- 快捷键可用。
- 退出行为正确。

### 7. 创建 GitHub Release

发布内容包括：

- 版本号，例如 `v0.1.0`
- 安装包或可执行文件
- Release notes
- 已知问题

## Git 提交要求

建议提交：

```text
test: add parser unit tests
test: add basic app flow test
chore: configure release build
```

发布版本可以打 tag：

```bash
git tag v0.1.0
git push origin v0.1.0
```

## 验收标准

- 至少有关键纯函数单元测试。
- 构建命令成功。
- Windows 包可以运行。
- GitHub 上有 Release。
- README 包含安装和运行说明。
- `99-进度记录.md` 记录当前版本和已知问题。
